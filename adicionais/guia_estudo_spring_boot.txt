============================================================
3. application
============================================================

Contém a classe principal da aplicação:

TseViewerApplication.java

Ela é a porta de entrada do Spring Boot.

Normalmente possui:

@SpringBootApplication
public class TseViewerApplication {

    public static void main(String[] args) {
        SpringApplication.run(TseViewerApplication.class, args);
    }
}

Quando essa classe é executada, o Spring Boot inicia a aplicação.

Normalmente a aplicação fica disponível em:

http://localhost:8080

IMPORTANTE:

A classe principal normalmente fica em um pacote acima das outras classes:

com.emanuel.TseViewer
|
+-- application
+-- controller
+-- model
+-- service

Isso permite que o Spring encontre automaticamente as classes dentro desses pacotes.


============================================================
4. CONTROLLER
============================================================

No projeto:

controller
+-- CandidatoController.java

O Controller recebe as requisições do navegador.

Exemplo conceitual:

@Controller
public class CandidatoController {

    @GetMapping("/")
    public String index() {
        return "index";
    }
}

Significado:

Quando alguém acessar:

http://localhost:8080/

o Controller recebe a requisição e retorna a view chamada "index".

return "index";

faz referência a:

src/main/resources/templates/index.html

IMPORTANTE:

@Controller é usado quando queremos retornar uma página/view.

@RestController é usado principalmente para APIs que retornam dados, como JSON.

Em aplicações com Thymeleaf, normalmente usamos @Controller.


============================================================
5. SERVICE
============================================================

No projeto:

service
+-- CandidatoService.java

O Service contém a lógica da aplicação.

Por exemplo:

- carregar dados;
- pesquisar;
- filtrar;
- ordenar;
- tratar informações.

O Controller não deve fazer toda a lógica sozinho.

A ideia é:

Controller
    |
    | chama
    v
Service
    |
    | executa a lógica
    v
dados

Exemplo conceitual:

@Service
public class CandidatoService {

    public List<Candidato> listarCandidatos() {
        // lógica para buscar candidatos
        return candidatos;
    }
}

E o Controller pode chamar:

List<Candidato> candidatos = service.listarCandidatos();

No projeto dos candidatos, o Service é responsável por carregar o CSV e realizar os filtros.

Por exemplo:

============================================================
11. THYMELEAF
============================================================

Thymeleaf permite que o HTML receba dados vindos do Java.

Por exemplo, no Controller:

model.addAttribute("candidatos", candidatos);

Isso cria uma informação chamada:

candidatos

disponível para o HTML.

No HTML podemos fazer:

<div th:each="candidato : ${candidatos}">
    <p th:text="${candidato.nome}"></p>
    <p th:text="${candidato.partido}"></p>
</div>

Significado:

Para cada candidato recebido do Java, criar uma parte da página.

Fluxo:

List<Candidato>
       |
       v
     Model
       |
       v
   Thymeleaf
       |
       v
      HTML


============================================================
12. application.properties
============================================================

Arquivo usado para configurações do Spring Boot.

Por exemplo:

server.port=8081

Nesse caso, a aplicação seria acessada em:

http://localhost:8081

Se não houver alteração, normalmente:

http://localhost:8080

Para atividades simples, pode ser que quase nenhuma configuração seja necessária.


============================================================
13. pom.xml
============================================================

O pom.xml é o arquivo de configuração do Maven.

Ele define:

- informações do projeto;
- versão do Java;
- dependências;
- plugins;
- configurações do Maven.

Exemplo de dependência do Spring Web:

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>

Dependência do Thymeleaf:

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-thymeleaf</artifactId>
</dependency>

Para leitura de CSV, o projeto utiliza OpenCSV:

<dependency>
    <groupId>com.opencsv</groupId>
    <artifactId>opencsv</artifactId>
    <version>...</version>
</dependency>

O projeto de candidatos utiliza:

- OpenCSV para ler o CSV;
- Spring Web para Controller, rotas e servidor;
- Thymeleaf para renderizar o HTML.

============================================================
16. .mvn
============================================================

A pasta:

.mvn

faz parte do Maven Wrapper.

Também aparecem:

mvnw
mvnw.cmd

Eles permitem executar o Maven utilizando a configuração do próprio projeto.

No Windows:

mvnw.cmd spring-boot:run

No Linux/macOS:

./mvnw spring-boot:run

Normalmente:

.mvn       -> manter
mvnw       -> manter
mvnw.cmd   -> manter

17. HELP.md
============================================================

HELP.md normalmente é um arquivo gerado pelo Spring Initializr com informações de ajuda.

Pode ser mantido, mas não é uma parte fundamental do funcionamento.


============================================================
18. .gitignore
============================================================

O .gitignore informa ao Git quais arquivos/pastas não devem ser enviados para o repositório.

Exemplos comuns:

target/
.idea/
*.class

É importante manter o .gitignore.


============================================================
19. .gitattributes
============================================================

O .gitattributes define algumas regras de comportamento do Git, como tratamento de arquivos e quebras de linha.

Pode ser mantido.

Não é necessário dominar esse arquivo para entender Spring Boot.

23. ANOTAÇÕES IMPORTANTES
============================================================

@SpringBootApplication

Informa que a classe é a principal aplicação Spring Boot.

@Controller

Indica uma classe responsável por receber requisições e retornar views.

@Service

Indica uma classe que contém lógica de negócio/serviço.

@GetMapping("/")

Define uma rota HTTP GET.

@RequestParam

Recebe parâmetros enviados pela URL.

Model

Permite enviar dados do Controller para o Thymeleaf.


============================================================
24. PRINCIPAIS COMANDOS E IDEIAS DO THYMELEAF
============================================================

th:text

Exibe texto vindo do Java.

Exemplo:

<p th:text="${candidato.nome}"></p>


th:each

Repete um elemento para cada item de uma lista.

Exemplo:

<div th:each="candidato : ${candidatos}">
    ...
</div>


th:if

Mostra um elemento somente quando uma condição é verdadeira.


th:href

Usado para criar links/caminhos utilizando Thymeleaf.


th:src

Usado para definir o caminho de imagens utilizando Thymeleaf.

============================================================
29. REGRA DE OURO
============================================================

Quando estiver fazendo uma atividade, faça estas perguntas:

1. O navegador pediu alguma coisa.
   Quem recebe?
   -> Controller.

2. Preciso fazer alguma lógica.
   Quem faz?
   -> Service.

3. Preciso representar uma entidade/dado.
   Quem representa?
   -> Model.

4. Preciso mostrar o resultado.
   Quem mostra?
   -> Thymeleaf + HTML.

5. Preciso deixar a página bonita.
   Quem cuida?
   -> CSS.

6. Preciso carregar dados.
   De onde?
   -> CSV, banco de dados ou outra fonte definida pela atividade.


============================================================
30. RESUMO FINAL
============================================================

APPLICATION
    -> inicia o Spring Boot.

CONTROLLER
    -> recebe requisições HTTP.

SERVICE
    -> executa a lógica.

MODEL
    -> representa os dados.

RESOURCES/DATA
    -> guarda arquivos de dados, como CSV.

RESOURCES/STATIC
    -> guarda CSS, imagens e outros arquivos estáticos.

RESOURCES/TEMPLATES
    -> guarda páginas HTML com Thymeleaf.

THYMELEAF
    -> conecta os dados Java ao HTML.

POM.XML
    -> configura o Maven e as dependências.

TARGET
    -> arquivos gerados pelo Maven; normalmente não versionar.

GITIGNORE
    -> define o que o Git deve ignorar.

MAVEN WRAPPER
    -> mvnw e mvnw.cmd permitem executar o Maven pelo projeto.
